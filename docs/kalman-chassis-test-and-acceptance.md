# 卡尔曼底盘实车测试与验收手册

适用工程：`NSEonLu - atype`；更新日期：2026-11-16。当前为双 A 板：下方板专门采集 IMU，经所选 CAN（默认 CAN1）送往整车主板。现场以两板实际烧录提交、构建参数和二进制哈希为准。

面向接手测试的电控、机械与测试人员。本文回答三件事：**先测什么、每一步怎么测、满足什么条件才能签字验收。** 本文是待执行的操作手册，不是实车通过报告。

本手册后文的固定 `Ixx` 索引及有效位按旧 schema 3/72 通道（本地路径为 schema 2）说明。日常默认 `config/_vofa/vofa_config.h` 的 `VOFA_OBSERVATION_PROFILE=2` 是 schema 5/96 通道，应按 [新通道表](vofa-observation-channels.md) 的同名物理量执行动作，不套用旧列号与缩放。若需逐项照本手册旧表核对，临时将该档位设为 `0` 并重新构建主板，测试完恢复 `2`。两档均为主板 UART7、230400 / 8N1；修复后的远端融合 schema 5 使用调用事件 FIFO，正常约 50 Hz，旧档仍为 20 ms 最新快照。需要重新采集调参数据时，直接按[卡尔曼重新采集步骤](kalman-recapture.md)执行。

本次远端融合直接采用 A 板原生 IMU 轴向，以底盘中心为原点，芯片偏移为 `(0,+0.116,0) m`，安装四元数为 `[1,0,0,0]`。公共轮速、速度输出保留原有定义；依据四份实测 CSV 的坐标一致性分析，公共 `(vx,vy)` 与 A 板分量 `(+vx,+vy)` 同号，入口、融合输出和配对轮速输出均不再对 X 取反。实物车头与公共字段的关系仍需正反向实车检查。详见 [双板坐标与检查](dual-a-imu-integration.md#轴向与补偿检查)。主板只在融合前扣除安装偏移引起的加速度，采集板 INS 已完成去重力。

## 0. 第一次接手：照这个顺序开始

本次默认测试对象是“第二块板的底盘 IMU + 四轮轮速”的卡尔曼速度观测。**先证明数据和动作正确，再评价融合精度。** 没有独立速度参考时，可以完成基础采集和融合运行检查，不能签精度通过。测试期间底盘仍使用原控制逻辑，不能以“车开起来更稳了”证明旁路融合有效。

| 顺序 | 执行人要做的事 | 留下什么，才能进入下一步 |
| --- | --- | --- |
| ① 选定本次路径 | 阅读第 1 节和第 4 节来源表；默认选 B 底盘 IMU，先执行 A 基础项；只有明确测试云台方案时才走 C | 在第 10 节记录表写明路径，确认两板安装、固件和配置一致 |
| ② 准备和构建 | 按第 3 节安排操作/记录人员、场地和设备；按 T0 做离线检查、构建、烧录和 VOFA 设置 | 保存提交号、构建命令、BIN 哈希、安装照片；先录到可解析的完整 CSV |
| ③ 架空过关 | 依次执行 T1 上电来源、T2 急停/恢复、T3 轮序/方向 | 三项均有通过记录；不能跳过急停检查直接下地 |
| ④ 地面基础 | 依次执行 T4 静止/云台、T5 前后、T6 横移、T7 旋转、T8 组合/故障/长时记录 | 每个动作保存原始 CSV；满足第 9 节 A 条件后，签“采集基础通过” |
| ⑤ 审核参数 | 执行 T9-B；实测安装/杆臂、辨识与验证参数，冻结验收阈值；重新构建后复查 T1～T3 | 保存参数、审核记录和新固件身份；没有独立参考或参数证据时停在“精度待验” |
| ⑥ 正式验收 | 按 T10 检查融合有效、静止/运动误差、故障恢复、延迟和资源 | 填第 9 节判定、第 10 节记录与签字；原始证据不齐的项填写“待测/无法判定” |

初次执行不要同时调多个参数。遇到失败，保存该试次及配置，记录原因和改动；相关前置项复测通过后再继续。每项具体动作、数据字段和通过条件均在下文，速查表不能替代逐项记录。

## 1. 先确认本次到底验收哪一层

当前项目已经把第二块固定底盘 IMU 接入在线卡尔曼速度观测，但不能把“收到 IMU”“出现融合输出”“精度通过”“参与控制”当作同一件事。

| 层级 | 当前实际能力 | 本文验收范围 |
| --- | --- | --- |
| A：双板采集基础 | 第二板固定在底盘，经所选 CAN（默认 CAN2）送 IMU；主板 UART7 输出一份 CSV。基础检查可用推荐融合固件，也可关闭远端融合只采集 | 先做：接线、来源、轮向、时间、数据完整性、运动工况、故障恢复 |
| B：推荐远端 IMU 融合观测 | 主板预设 `CHASSIS_REMOTE_IMU_FUSION_ENABLE=1`，将第二板 IMU 与轮速历史配对并融合；使用固定安装旋转和芯片偏移，不依赖本地云台 IMU/编码器 | 实测参数审核后做：真正融合、误差、偏心补偿、时间不确定度、降级和实时性 |
| C：可选本地云台 IMU 融合观测 | 关闭远端接收和远端融合、提供本地标定头，用主板云台 IMU 与 yaw/pitch 编码器融合 | 只在验证这条路径时另做；不能替代 B 的远端验收 |

**软件配置尚无实车通过结论。** `CHASSIS_REMOTE_IMU_CONFIG_VERIFIED=0` 时也可能出现 FUSED；A 板原生坐标下的 +Y 116 mm 已按量到芯片的位置填写，仍需通过实测检查轴向、边界换算和补偿。`CHASSIS_VELOCITY_FUSION_CALIBRATED=0` 只表示未开启本地云台标定路径，不表示远端融合关闭。远端与本地路径互斥，几何坐标与安装参数不能混用。

三个层级均不验收融合闭环控制。融合快照没有进入电机反馈、速度补偿或功控；不能由本手册签出“卡尔曼主动控制”或“防滑通过”。

工程还有一个单轮转速 KF：`CHASSIS_SPEED_KF_SHADOW_ENABLE`，使用转子 rad/s 和 CSC1 采集。它与本手册的整车平移速度融合不同；其工具、参数和 300 μs 等预算不套用到这里。单轮实验另见 [单轮速度观测说明](chassis-speed-observation.md)。

## 2. 测试顺序：前一项不过，不进入后一项

```text
T0 固件与记录准备
 → T1 接线、静止上电、来源检查
 → T2 架空急停与恢复
 → T3 架空逐轮、轮序与方向
 → T4 地面静止与云台动作
 → T5 低速前后 → T6 低速横移
 → T7 旋转 → T8 组合动作、通信故障与长时记录
 → A 级采集验收
 → T9 第二板安装/参数实测审核与远端融合构建
 → T10 融合精度、降级、实时性
 → B 级远端融合观测验收
可选支线：T9-C 本地云台标定构建 → 重测 T1～T3 与 T10 → C 路径验收
```

第一次外场以 T0～T8 为目标。没有独立速度参考时，也可以完成 A 级；即使出现 FUSED，B/C 也只能写“融合已运行、精度待验”，不能写“融合准确”或“防滑有效”。

## 3. 人员、场地和记录准备

建议至少两人：一人操作遥控和断电，一人看数据、记录动作。准备稳固架空支架、两块 A 板、下载器、主板 UART7 接收器、VOFA+、电池及电压观察手段、卷尺/地面刻度、录像设备。B/C 还需要独立速度或位姿参考，例如有比例标定和时间记录的俯视录像、光学定位；轮速里程计不能给自己当真值。

测试前卸除弹丸并确认发射机构关闭，整理云台和车轮附近线束。第二块板必须刚性固定；拍照标出芯片位置、板的轴向以及相对底盘中心的三维偏移。清空运动区域，预先写下本场地允许的速度、旋转速度、停车距离和功率上限。

### 3.1 遥控器操作必须先核对

以下对应当前 [命令实现](../application/cmd/robot_cmd.c) 和 [遥控配置](../config/05_remote/remote_config.h)，实物拨轮方向先在架空状态核对。

| 操作 | 当前含义 |
| --- | --- |
| 左开关中/下 | 摇杆控制；左开关上是图传键鼠来源 |
| 右开关上 | 不跟随模式，`I7=2`；**不是急停，也不是零力** |
| 右开关中 | 跟随模式，`I7=3`；云台转动可能带动车身 |
| 右开关下 | 自旋模式，`I7=1`；首次测试先不使用 |
| 右摇杆 | 前后、左右平移；以实际动作和 `I21/I22` 校验符号 |
| 拨轮正值超过 `+300`（当前阈值） | 急停；负方向会请求摩擦轮/发射，不能凭手感猜方向 |
| 故障消除后复位 | 输入在线、右开关上、全部摇杆和拨轮回中、键鼠释放；还需本地 INS 和 yaw 等安全条件有效 |

当前自旋默认自适应，初始 `CHASSIS_SPIN_FIXED_WZ=8000`，这是工程命令尺度，不是 rpm 或 rad/s。**不要直接拨入默认自旋档完成“低速自旋”测试。** 先做零输出手推旋转；有动力旋转须由电控人员提供已在架空核对的受限配置，并记录实际 `I23/I26` 换算后的转速。配置入口见 [自旋配置](../config/21_chassis_spin/chassis_spin_config.h)。

## 4. T0：构建和采集配置

先选 IMU 来源。下面是**主板**编译参数，不是第二板的采集固件参数；当前双板脚本的主板预设为 B。

| 主板编译开关 | A：仅记录第二板，估计用轮速 | B：第二板底盘 IMU 融合 | C：本地云台 IMU 融合 |
| --- | ---: | ---: | ---: |
| `CHASSIS_VELOCITY_FUSION_ENABLE` | 1 | 1 | 1 |
| `CHASSIS_IMU_CAN_RX_ENABLE` | 1 | 1 | 0 |
| `CHASSIS_REMOTE_IMU_FUSION_ENABLE` | 0 | 1 | 0 |
| `CHASSIS_VELOCITY_FUSION_CALIBRATED` | 0 | 0 | 1 |

A 基础项也可用 B 固件执行，此时记录融合状态，但不提前给出精度结论。B 用[远端安装/噪声配置](../config/30_velocity_observation/chassis_remote_imu_config.h)；C 必须另备实际标定的 `chassis_velocity_fusion_calibration.h`，按 7.3 的独立目录和手动构建命令执行。`CALIBRATED=1` 是启用已提供的本地标定，不会自动完成标定。

使用 `build-board.ps1` 时，这些开关来自[两板配置](../config/00_flash/board_flash_config.h)里加了 `BOARD_FLASH_1_` 前缀的同名定义。`BOARD_FLASH_TARGET` 或 `-Board 1/2` 只选择构建/烧录哪块物理板，**不选择融合来源**。手动 Make/CMake 不读取该两板配置文件，须显式传参。

当前两路 IMU 是编译期二选一，没有遥控器切换或双 IMU 同时融合；切换必须重新构建并烧录主板，归档为新试次。B 丢失远端 IMU 时退回轮速，不自动换成云台 IMU。默认 B 与纯采集 A 之间切换不要求修改第二板发送固件。

### 4.2 推荐双板构建与烧录

以 [两板配置文件](../config/00_flash/board_flash_config.h) 为入口，先查看两板实际选项：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Show -Board 1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Show -Board 2
```

| 必须核对的选项 | 主板 Board 1 | 底盘 IMU 板 Board 2 |
| --- | --- | --- |
| `ONE_BOARD` / `CHASSIS_CONTROL_MODE` | `1` / `0` | `1` / `0` |
| `IMU_CAPTURE_ONLY` | `0` | `1` |
| `IMU_CAPTURE_CAN_TX_ENABLE` / `CHASSIS_IMU_CAN_RX_ENABLE` | `0` / `1` | `1` / `0` |
| `CHASSIS_VELOCITY_FUSION_ENABLE` / `CHASSIS_VELOCITY_FUSION_CALIBRATED` | `1` / `0` | `0` / `0` |
| `CHASSIS_REMOTE_IMU_FUSION_ENABLE` | `1`，推荐融合；纯采集改 `0` | `0` |
| `VOFA_TELEMETRY_ENABLE` / `VOFA_TELEMETRY_MODE` | `1` / `2` | `0` / `1`（关闭时格式不参与输出） |
| `USB_TELEMETRY_ENABLE` | 当前预设 `1` | `0` |
| 输出目录 | 当前 `build/board-1-main` | 当前 `build/board-2-imu` |

主板另核对 [远端配置](../config/30_velocity_observation/chassis_remote_imu_config.h)：`CHASSIS_REMOTE_IMU_CONFIG_VERIFIED` 默认 `0`，此时只做名义参数试运行，不签 B 通过。若先做纯采集，把两板配置中的 `BOARD_FLASH_1_CHASSIS_REMOTE_IMU_FUSION_ENABLE` 改为 `0` 并重新构建；恢复 B 时改回 `1`。两次固件与 CSV 分开归档，不能只改开关而继续使用旧 BIN。

确认供电配置与实车一致，不能只凭 `atype-vehicle` 名称判断是否超电供电。当前默认直供，超电供电需显式配置 `CHASSIS_POWER_SOURCE_MODE=1`，并按原功控说明核对设备。无裁判时不要临时绕过正常门控来跑地面；`atype-bench` 的无裁判功率回退只用于架空台架。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Build -Board 1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Build -Board 2
```

两份均构建成功后，**一次只连接要烧录的那块物理板**，分别执行对应命令：

```powershell
# 仅连接第一块整车主板时执行
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Flash -Board 1
# 换接第二块底盘 IMU 板后再执行
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-board.ps1 -Action Flash -Board 2
```

`-Board` 只是选择构建参数，脚本不会识别接在下载器上的板。`Flash` 会先重新构建，成功后下载。默认下载器为 DAPLink/OpenOCD，J-Link 在配置文件内选择。不要全片擦除需要保留的 Flash 参数区。

按 `Show` 实际输出目录计算哈希；当前默认目录示例：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath build/board-1-main/basic_framework.bin
Get-FileHash -Algorithm SHA256 -LiteralPath build/board-2-imu/basic_framework.bin
```

### 4.3 接线与 VOFA+

断电接线：按两板固件的 `CHASSIS_IMU_CAN_PORT` 连接对应 CAN1 或 CAN2（默认 CAN2），H 对 H、L 对 L、参考地相连；切换与构建入口见 [双板说明](dual-a-imu-integration.md#接线与构建)。核对两端终端电阻，不因新增节点盲目增加第三只。当前速率 1 Mbps，远端 IMU 标准 ID 为 `0x180`。名义每 20 ms 尝试一组、每组 9 帧；接收组装期限 10 ms。

只把**主板 UART7 TX（PE8）接接收器 RX，GND 接 GND**。接口针序和接收器供电按实际硬件核对。UART7 不得同时被裁判或辅助设备占用。第二板不需要再接第二个 VOFA 窗口。接线图入口见 [A 板接线](atype-integration.md#接线)。

VOFA+ 选择 `SerialPort → 正确 COM → 230400 / 8N1 / 无流控 → JustFloat`（主板模式 `2`，按旧表核对时用途设为 `0`）。每帧应有 `I0`～`I71` 共 72 个固件数据通道；导出文件可能另含 VOFA 时间列，不把它计入 72 列。

无线从机须支持并匹配 230400。先记录板端时间与发送尝试序号，检查是否约 20 ms 连续输出及有无缺口；带宽与实时性检查见 [波特率影响与检查](vofa-telemetry.md#230400-波特率的使用与影响)。

每工况开始前清空旧缓存；结束后在 VOFA+ 中“文件 → 保存数据”导出 CSV，保留全部通道、表头和时间列。不要只保存勾选的几条波形，不用截图替代 CSV。完整字段表见 [完整观测通道定义](vofa-telemetry.md#firewater-卡尔曼观测通道表)。

## 5. 测试时先看这几组数据

| 检查目的 | 字段与判读 |
| --- | --- |
| 是否刷对固件/来源 | A/B 必须 `I0=3`、`I63=0`、`I64=2`、`I5` bit 15 为 1；推荐远端融合另有 bit 16/17 为 1 |
| 参数是否已审核 | bit 18 为 1 表示配置声明已实测审核；默认 0，不控制算法运行，也不是精度通过证明 |
| 四轮是否可信 | `I8=15` 表示四轮在线且新鲜；`I17`～`I20` 为各轮反馈年龄；`I5` bit 1 为轮速反算有效 |
| 是否有远端 IMU | `I5` bit 4 必须为 1；单有 bit 15 不能证明收到数据 |
| 当前是否真的融合 | `I6=9` 且 `I5` bit 3 为 1；仅纯采集（远端开关 0）四轮正常时应 `I6=2`、bit 3 为 0 |
| 前后/左右速度 | 轮速 `I21/I22`，目标 `I24/I25`，估计 `I27/I28`；均除以 1000 得 m/s，前/右为正 |
| 融合配对量（B/C） | `I29/I30` 配对轮速，除以 1000 得 m/s；`I31/I32` 导航系中心加速度，除以 1000 得 m/s²；仅 bit 3 有效时使用 |
| 车体旋转 | `I23/I26` 为 mrev/s，乘 `60/1000` 得 rpm，乘 `2π/1000` 得 rad/s；不是电机转子 rpm |
| IMU 响应 | `I36`～`I39` 四元数除以 1000000；`I40`～`I42` 导航系去重力加速度除以 1000；`I43`～`I45` 传感器系角速度除以 1000 |
| CAN IMU 时序 | `I65` 完整组接收年龄；`I66` 发送时源年龄；`I33` 已知年龄下界；`I69` 首末片跨度，单位 ms |
| 输出和功控 | `I9` 最终使能位，`I52`～`I55` 最终尝试提交的电流命令；`I56`～`I59` 除以 100 得 W；分别结合 `I5` bit 7/8/9/10/12 使用 |

JustFloat CSV 中的整数语义字段先四舍五入再用于位运算或时间/序号组合，避免帧尾防碰撞带来的微小浮点变化。float32 不能精确表示全部 int32 大整数；高低 16 位字段仍可还原，详见[精度说明](vofa-telemetry.md#firewater-卡尔曼观测通道表)。bit 判断方法是 `(round(I5) & (1 << n)) != 0`（先将 `round` 结果转为整数）。例如 bit 4 对应掩码 16，bit 3 对应 8。**无效数据可能填 0；年龄未知是 -1。先看有效位，再看数值。** “CAN 提交成功”只表示入队成功，不证明电调实际执行。

高低位还原：主板时间 `t=I1×65536+I2`，发送尝试序号 `seq=I3×65536+I4`，源 INS 序号 `s=I34×65536+I35`，拒绝组数 `reject=I70×65536+I71`。时间/序号按 uint32 回绕，拒绝计数饱和。设备重启要分段，不能当作一次正常回绕拼接。

### 5.1 时间和坐标的三个限制

1. 主板模式 `2` JustFloat 在 230400 / 8N1 下目标周期 20 ms，标称 50 Hz（旧模式 `1` FireWater 为 115200、80 ms / 12.5 Hz）；异步读取的最新快照仍可能重复或漏采输入，不保证包含每次 CAN 更新。源 INS 序号跳变是正常现象，不能用它计算 CAN 丢包率。发送尝试序号缺口表示 UART 忙或后续传输/接收等环节遗漏，不等于电机 CAN 丢帧。
2. 两板时钟未同步；不能用主板时间直接减第二板 `I67/I68`。`I33` 不含全部排队和传感器内部延迟，是已知年龄下界；有效远端输入要求 `I66≤20 ms` 且 `I33≤60 ms`，不证明真实端到端延迟小于 60 ms。远端融合按 `first_rx-source_age` 估计主板时刻作轮速历史配对，源板时间用于差分/KF 的 dt；bit 17 提醒时间是估计。主板时间减 `I11` 得到的远端融合时刻也有这项不确定度，不能当成同步后的真值时刻。
3. 速度公共接口保留原有定义；B 的几何与芯片偏移按 A 板原生轴，入口按 A 板 `(+vx,+vy)` 处理公共轮速，出口和配对轮速均保持 X/Y 同号。C 的本地云台标定几何仍使用前/左/上。`I40`～`I42` 属于源板导航系，`I43`～`I45` 属于传感器系，不能直接当成车体系前/右加速度。先确认安装旋转、实物运动方向和参考坐标，再做定量比较。

## 6. T1～T8：按表执行实测

所有动作前后各保留约 5 s 静止；探索阶段同一动作重复 3～5 次，每次单独编号。出现方向错误、失控、持续振荡、掉线、功率/温度超过本车限制时停机，保存失败数据，回到上一阶段排查。

| 编号 | 操作步骤 | 看什么、如何通过 | 不通过先查什么 |
| --- | --- | --- | --- |
| T1 静止上电 | 稳固架空；摇杆/拨轮回中、右开关上，按停机准备控制动力；两板上电后保持不动，等待 INS 启动标定，再录 60 s | schema/角色/来源正确；bit 4 稳定有效；`I65` 周期性更新而非持续变大；纯采集四轮正常时 `I6=2`，融合固件另记录状态分布；静止段不持续增加拒绝数 | 两板固件是否错刷、UART 协议、所选 CAN 接线/终端、第二板是否仍在标定 |
| T2 急停/恢复 | 架空、极小平移输入，触发已确认方向的急停；停车后先将急停拨轮回中，但保持小幅平移摇杆非中立，确认仍为零输出；最后将摇杆全部回中、右开关上并满足复位条件，再给极小输入确认恢复；重复 3 次 | 有效最终快照下 `I9=0`、四轮电流命令归零；实际运动停止；急停请求解除但非中立输入仍在时不得重新驱动，这一步才证明锁存。另测遥控掉线及恢复 | 输入符号、门控状态、主板本地 INS/yaw 健康；停止异常立即断电，不继续地面测试 |
| T3 逐轮与组合 | 保持零输出，手转 LF/RF/LB/RB，每次只转一轮；再解除急停，以极小前后/横移输入观察四轮组合方向 | `I13`～`I16` 只有对应轮变化；轮位按 LF/RF/LB/RB，当前电机 ID 为 1/4/2/3；组合方向符合实车运动学，四轮年龄正常 | 电机 ID、轮序、方向宏、减速比/轮径；不要用调 KF 掩盖反向电机 |
| T4 地面静止/云台动作 | 下地静止 60 s；右开关上不跟随，云台 yaw 单轴、pitch 单轴、两轴组合小幅往复，各 30～60 s；记录底盘是否真的静止 | 轮速平移接近零；第二板来源不变；底盘不动时远端 IMU 不应出现由错误来源造成的整段随云台转动响应，机械振动另记 | 第二板是否刚性安装、是否刷为主板；跟随模式/车身实际微动。A 路线本步骤不验收云台杆臂补偿 |
| T5 前后 | 空地、不跟随、云台方向固定；从实测约 0.2 m/s 起，按场地允许逐级到约 0.5 m/s：前进—停稳—后退—停稳；每档 30～60 s | 前进 `I21>0`、后退 `<0`；`I22` 接近静止/横向误差范围；加减速响应与动作有对应关系；所有方向相对底盘标记判断 | 模式/云台偏角、符号、轮径、滑移、供电限功率；摇杆量不是 m/s，以上速度是初测建议 |
| T6 横移 | 相同低速档，右移—停稳—左移—停稳，每档 30～60 s | 右移 `I22>0`、左移 `<0`；`I21` 不出现明显串轴；比较左右方向差异 | 同 T5，另查轮安装角和轮向；横移往往更易暴露打滑 |
| T7 旋转 | 先在已确认零输出且反馈仍在线时缓慢手推绕中心旋转，正反各 20～30 s；动力旋转仅用事先验证的低速配置，正反分别停稳后测试 | `I23` 与实际方向对应，第二板角速度有一致响应；记录 IMU 偏心引起的加速度；中心平移若不为零，先核实车身是否漂移 | 不把偏心旋转加速度当作平移真值；不能因几何中心附近就假设杆臂为零。没有可控反向动力档时只记录手推反向，不写动力反向通过 |
| T8 组合/恢复/耐久 | T5～T7 通过后做低速斜移、转弯及已获准的旋转加平移；再按下表做故障测试；最后连续记录至少 10 min，交替静止与已通过的低速动作 | 未出现错向、来源切换、持续拒绝增长或不可解释速度跳变；所有 CSV 满足 A 级门槛；供电、功率和控制表现符合原车要求 | 保留最差试次；比较加装第二板前后的 CAN 负载/轮龄。降低采集频率不能代替解决电机通信故障 |

这里的 0.2/0.5 m/s 和 10 min 是首轮测试建议，不是固件限速或正式耐久承诺。正式验收的速度、载荷、地面和时长必须提前写入记录；扩大工作范围时补测，不能从低速外推到高速。

### 6.1 故障与恢复单独记录

| 故障项 | 如何施加 | 预期结果与判定边界 |
| --- | --- | --- |
| 远端 IMU 失联/重启（A/B） | 底盘先停稳、零输出。只切断第二板独立供电或已设计的隔离支路，保留整条 CAN 总线和终端；恢复供电后保持静止完成标定，重复 3 次 | 旧完整组超龄后 bit 4 清零，来源仍为远端 A 板 CAN。纯采集四轮正常时 `I6` 可为 2；远端融合应清 bit 3、退回有效轮速，源重启后重新预热再融合，不偷换成本地 IMU。远端不是当前驱动安全输入，不能要求它失联必然停电机 |
| 遥测接收中断（A/B/C） | 静止时断开电脑端接收/关闭 VOFA 连接，再重新连接并新建记录 | 数据缺口明确分段；不能把接收端断线误判为车上 IMU 失效，也不能据此证明板端 UART 拥塞处理已经实测 |
| 单轮反馈缺失（A/B/C） | 架空、零输出、断电后安排单电机独立反馈支路失联，再上电观察；保留其他总线节点和终端，不带动力拔共享 CAN | 该轮在线位清零，轮速 bit 1、估计 bit 2、融合 bit 3 清零，状态为轮不可用。不能只看速度填 0 就说停车保护通过；驱动行为另看安全链和最终输出 |
| 遥控失联/急停（A/B/C） | 仅在 T2 已验证的架空低速条件下做，记录触发与恢复 | 驱动停止、恢复须重新满足中立及健康条件；CSV 只能证明采样时刻状态，停止延迟要靠高频日志或同步录像测量 |
| 本地 IMU/云台反馈无效（B/C） | 由电控人员用已验证的台架故障注入或独立支路方法施加；不在运动中破坏共享线路 | B：远端与轮速仍有效时，不应仅因本地输入无效就失去远端融合；C：bit 3 清零并退回轮速。两种配置都可能因原车本地 INS/yaw 安全条件失效而停驱，分别记录观测状态与安全门控 |
| 重复源包、漏组、时间跳变（B） | 先执行远端模块与应用主机测试；上板只由电控人员用已验证的注入固件/设备、架空零输出施加，并保留注入日志和逐次诊断 | 同源包不重复推进 `remote.updates`，不刷新融合输出时刻；超龄后降级。约 40 ms 源间隔、重启或异常时序应清历史/预热；合格新数据恢复后再 FUSED。50 Hz CSV 无法单独证明每次更新行为 |

远端协议的错序、缺片、CRC、10 ms 期限和时间回绕先由主机协议测试覆盖，融合层时序另由远端模块/应用测试覆盖；普通外场不通过短接总线制造故障。没有合适注入设备时，将硬件注入项标为未执行并保留软件结果；不得把软件结果写成该项硬件已通过。

### 7.3 T9-C：可选本地云台路径

C 只适用于主板 IMU 随云台 yaw/pitch 运动的原有实现。执行人应与电控负责人完成以下标定，记录测量方法、误差和照片，详见 [本地融合参数定义](chassis-velocity-fusion.md#现有云台-imu-融合路径构建与读取)。

| 项目 | 要做的事 |
| --- | --- |
| 轮运动学 | 核对实际轮半径、减速比、轴距、轮距、轮序和方向；源码当前默认 60 mm、19、350 mm、300 mm，不代表实物已测量 |
| 两级转轴/芯片偏置 | 测底盘中心→yaw 轴、yaw 轴→pitch 轴、pitch 轴→MPU6500 芯片的三维向量；转换为各自规定坐标系，单位 m |
| IMU 安装旋转 | 确认传感器到云台头的 `[w,x,y,z]` 单位四元数，不能只猜一个 yaw 角 |
| 编码器 | yaw/pitch 零位 `0…8191` 和方向 `±1`；标定系前/左/上，正 pitch 绕左轴低头 |
| 时间 | 核实轮反馈、INS、两轴编码器年龄、偏斜和内部延迟；不能通过放宽超时让无效数据假装有效 |
| 滤波参数 | 用辨识数据确定 `wheel_variance`、`accel_variance`、`jerk_density`、`max_velocity_residual_mps`；再用独立验证段检查，正式测试前冻结 |

将真实标定写为 `static const ChassisVelocityFusionCalibration_s chassis_velocity_fusion_calibration`，放入目标构建目录的 `chassis_velocity_fusion_calibration.h`。标定结构体定义在 [观测器实现](../application/chassis/chassis_velocity_observer.c)，几何与滤波字段分别见 [安装几何头](../modules/algorithm/chassis_gimbal_imu.h) 和 [滤波配置头](../modules/algorithm/chassis_velocity_fusion.h)。**不复制 `tests/chassis_velocity_observer/stubs` 的合成数值到实车。**

先创建 `build/kalman-local-verified` 并放入审核后的头文件，再执行：

```powershell
make -j8 PROFILE=atype-vehicle BUILD_DIR=build/kalman-local-verified ONE_BOARD=1 CHASSIS_CONTROL_MODE=0 IMU_CAPTURE_ONLY=0 IMU_CAPTURE_CAN_TX_ENABLE=0 CHASSIS_IMU_CAN_RX_ENABLE=0 CHASSIS_REMOTE_IMU_FUSION_ENABLE=0 CHASSIS_VELOCITY_FUSION_ENABLE=1 CHASSIS_VELOCITY_FUSION_CALIBRATED=1 VOFA_TELEMETRY_ENABLE=1 VOFA_TELEMETRY_MODE=2 VOFA_OBSERVATION_PROFILE=0

```

本步骤使用手动 Make，不经过仍指向远端融合配置的 `build-board.ps1 -Board 1`。供电、受限自旋及其他本车覆盖参数也应带入并归档；切换后重新检查固件身份和 T1～T3 的适用项。C 路线为 schema 2，保存 `I0`～`I63`，`I0=2`、`I63=0`，bit 15～18 为 0，IMU 来源变为本地云台；第二板此时不参与融合。不要对 C 套用 A/B 的远端来源检查。

## 8. T10：融合效果怎么测

### 8.1 先确认确实进入融合

等待历史建立后，应出现 `I6=9` 且 bit 3 为 1，同时 bit 2 有效。不能只看到 `I27/I28` 有数值就算成功：状态 2～8、10 可能继续输出轮速降级值。调试器可读 `chassis_fused_velocity`；跨任务代码应调用 `ChassisGetFusedVelocitySnapshot()`，并联合检查 `valid` 与 `status`，旧状态值本身不证明新鲜。

B 另查看 `chassis_fused_velocity.remote` 的 `source_sequence/source_tick_ms/estimated_sample_ms`、`source_step_ms/receive_step_ms/pair_span_ms`、`updates/resets` 与 `timing_estimated`。这些是最近检查的源身份/时间、配对和累计诊断；它们不一定对应当前三点补偿的中间输出，输出时刻另看 `tick_ms`。稳定新数据应使更新计数推进，同源重复包不重复推进或刷新输出时刻；故障恢复会重新预热。详细诊断不在 72 列 CSV 内，必要时先安排无停核采集，再验相应行为。

| `I6` | 意义 | 优先处理 |
| --- | --- | --- |
| -1 / 0 / 1 | 未开启 / 尚无样本 / 轮反馈不可用 | 构建配置、任务是否运行、四轮输入 |
| 2 | 仅轮速观测 | 检查远端融合是否关闭、本地标定是否关闭；不是 bit 18 的“未审核”状态 |
| 3 / 4 / 5 | 时钟 / IMU / 云台反馈不可用 | B 查远端 IMU；3/5 是本地路径诊断，B 不应仅因云台输入无效而降级 |
| 6 | 未对齐 | B 查轮速历史配对、四轮反馈偏差；C 查输入年龄与时序偏差。先查延迟，后讨论阈值 |
| 7 | 热机历史不足 | 观察是否短暂进入后恢复；长期停留要查历史被反复清空的原因 |
| 8 | 姿态、中心校正或滤波拒绝 | 几何、四元数、时间、输入质量及残差门限；不直接调大门限放行 |
| 9 | 使用了 IMU 融合 | 仍检查 bit 3 和独立精度 |
| 10 | 远端配置无效 | 查安装四元数、噪声、时间门槛是否合法；bit 18=1 也不能让非法配置生效 |

### 8.2 先测静止、云台动作和偏心旋转

重复 T4：底盘和云台全静止，再分别 yaw、pitch、两轴组合，每段 30～60 s，至少 3 次。用录像/独立位姿确认底盘确实没移动。

看 `I31/I32` 的导航系中心加速度、`I27/I28` 的估计速度、bit 3 和状态分布。B 中第二板固定在底盘，先排查错来源、安装旋转、振动和车身真实微动；C 中还要排查云台杆臂、编码器零位/方向及对齐。不能只把滤波调钝来消掉波形，拒绝/降级时填零不算“补偿正确”。

B 再重复 T7 已通过的受限旋转：用独立位姿确认中心是否平移，比较实测非零固定芯片偏移补偿后的中心加速度与速度。不要用最新原始 `I40/I41` 和延后的 `I31/I32` 逐行相减宣称补偿收益；两者时刻不同。固定偏移引起的向心/切向加速度不是底盘中心平移真值。

### 8.3 再测独立速度参考

重复 T5～T8 的已通过运动工况。将数据分成不同试次的“辨识、验证、正式测试”三组，不把同一次行驶相邻行随机拆开。参数和判定阈值在正式测试前冻结，正式结果不理想也保留原始记录。

1. 标定参考系统比例、坐标轴和时间；将参考速度转为与估计相同的底盘前/右坐标。旋转工况还需独立姿态；只有直线尺量时，只验收平均速度/距离，不宣称瞬时动态精度。
2. 主板时间减 `I11` 得融合输出时刻，`I29/I30` 是其配对轮速。B 的时刻经过 `first_rx-source_age` 估计，必须把未知单向排队/内部延迟和参考同步误差写进误差预算；C 使用主板本地时间。不要直接拿最新 `I21/I22` 与延后融合值逐行相减，也不要把原始 IMU 列当成融合中间样本。
3. 中心校正使用三点居中差分，每侧约 15～30 ms，所以估计本来就有历史延迟；B 还须有合格轮速历史。50 Hz 漏一组形成约 40 ms 间隔时会清历史/预热，不能把这些降级段全部删除。离线对齐方法与允许调整范围须预先固定，并单独报告输出年龄/可用延迟；逐试次按最优相关系数任意移位不能用来掩盖在线迟滞或未知时间误差。
4. 逐轴计算误差 `e=v_est-v_ref`，记录均值、RMSE=`sqrt(mean(e²))`、绝对误差 P95/最大值；轮速基线使用同一参考、同一时刻和同一工况。每主工况建议至少 5 次独立正式重复，评估改善时保留至少 10 组可比试次。
5. 正常测试段的失效、拒绝和降级全部进入可用率统计；精度表明确有效样本覆盖率。不能只截取好看曲线、删除所有难测段后宣布通过。

当前 CSV 没有完整高频输入、协方差或校正前 innovation。`估计－配对轮速` 是后验差，不能直接据此拟合 R；`chassis-speed-capture.py`、`wheel-speed-replay.py` 也不是这个 VOFA+ 观测 CSV 的解析/回放工具。需要高频复现、毫秒级迟滞或精确 Q/R 辨识时，由电控人员另行提供逐次输入/输出及同源时间记录。

### 8.4 最后测故障、任务耗时与资源

执行 6.1 中所选 B/C 路径的适用项，确认输入失效时不继续宣称 FUSED；恢复经过预热后重新稳定，不产生异常速度尖峰。B 必须分别检查远端失效/重启与本地 IMU/云台失效的不同后果。遥控急停与原功控仍单独验收，融合是观察路径不代表可以省略原车测试。

在相同供电、载荷、遥测和动作下，对比开启/关闭融合的固件；B 使用 7.2 的融合/纯采集配置，保留相同 CAN 流量和遥测。每种配置记录至少 10 min。记录应用、INS、电机任务的**最大执行时间、启动间隔、超期次数、最小剩余栈和最小空闲堆**，包含遥测和 CAN 最繁忙时刻。

当前任务源码在 INS >1 ms、电机 >2 ms、应用 >5 ms 时告警，这些是代码中的执行耗时告警线。任务使用 `osDelay`，不能把这些数值当作已经实测的精确启动周期。也不能把单次变量、日志没报错或模式 `2` 的 50 Hz 遥测曲线当作最坏耗时证据。

若现有固件没有导出所需最大值，由电控人员先补充无停核的统计或 GPIO/逻辑分析仪测量，再验实时性。当前 CAN 采集 CSV 不含这些指标。栈高水位按 FreeRTOS words 记录并注明单位；参考 `.su`/map 只能辅助，不能代替实测。调试器 halt 的试次不用于实时验收。

## 9. 最终验收标准

### 9.1 哪些是代码条件，哪些是建议门槛

代码条件直接按当前实现判定，例如远端源年龄 20 ms、已知年龄下界 60 ms、四轮 20 ms 新鲜度、schema/有效位；不通过就不能使用对应数据。

B 还要核对实际配置中的配对跨度、四轮偏差、时间抖动及滤波门槛；三点中心补偿每侧 15～30 ms 由当前算法规定。出现 FUSED 只说明通过软件当前门槛，不证明这些门槛能覆盖真实时钟误差。以下 B/C 共用精度与资源建议，C 不套用远端配置位和跨板配对条件。

下面数值是**首次验收的建议起点，不是已有实测结果，也不是比赛规则**。负责人在正式测试前结合实际使用范围和仪器能力确认或改写，并记录冻结时间；不能看完正式结果再降低门槛。参考测量不确定度应明显小于对应允许误差，建议不超过其 1/3；达不到则该项“无法判定”。

| 验收项 | 建议判定标准 | 不满足时的结论 |
| --- | --- | --- |
| A：身份与来源 | 两板 BIN/配置/安装记录齐全；每段 schema、角色、来源一致；所有用到的测量都有有效位依据 | 采集不可用于定量验收 |
| A：记录完整性 | 每个正常工况有效 CSV 收到率 ≥99%；最大相邻记录间隔 ≤240 ms；稳态拒绝组计数不增长；短缺口单独标记，禁止跨缺口积分 | 修复采集链后重测该工况 |
| A：输入可用性 | 热机结束后的正常工况，轮速 bit 1 与远端 IMU bit 4 各自有效行比例 ≥99%；更长的无数据时间由上一行间隔指标约束；故障试次另列 | 不能进入参数辨识；统计只代表已观测的 CSV，不代表每个 50 Hz CAN 组 |
| A：动作与故障 | T2/T3 的轮序、方向、急停及恢复全部通过；T4～T8 完整且异常可解释；故障步骤 3 次均符合预期 | 未完成项标待测，错误项标失败 |
| B：配置与时间证据 | 安装/噪声/时间配置有实测、审核及冻结记录；bit 16/17/18 为 1；独立参考时间不确定度及预定对齐方法满足本次误差预算 | 只能写试运行，不能用 bit 18 或 FUSED 代替证据 |
| B/C：融合可用率 | 排除事先固定的启动预热段后，各正常工况 bit 3 有效行比例 ≥99%；故障触发的无效另统计，不能扩大“预热”范围来隐藏失败 | 不能只凭少数 FUSED 行验收 |
| B/C：静止/云台动作 | 静止与云台动作各段，每轴速度均值绝对值 ≤0.03 m/s，绝对速度 P95 ≤0.05 m/s；确认不是掉线填零 | 查几何/坐标/时间后重新验证 |
| B/C：运动精度 | 各工况每轴 RMSE ≤ `max(0.10 m/s, 该轴参考速度RMS的10%)`，绝对误差 P95 ≤0.20 m/s；所有正式重复均报告，最差次也须满足已冻结界限 | 写明未达精度，不能以“曲线更平滑”替代 |
| B/C：相对轮速基线 | 同一评分区间融合 RMSE 不高于轮速基线的 105%；若宣称“有改善”，预先指定的主指标建议至少改善 10%，且不能以其他工况明显退化为代价 | 可如实结论“无可测收益”；基线接近仪器噪声底时不做百分比收益断言 |
| B/C：降级与恢复 | 适用故障/恢复各 3 次，均不持续输出失效融合；恢复无超出预先约定峰值的跳变，恢复时间有实测记录 | 不放行对应路径；记录影响源、重置/预热与状态 |
| B/C：延迟/资源 | 测前填定最大允许输出年龄/恢复时间/任务间隔及耗时、最小栈/堆余量；整段无越界；上述代码耗时告警不得触发且留有余量 | 这些指标未测或未定阈值，整体验收不完整 |

收到率可按首末发送尝试序号计算：`收到的不同 seq 行数 / (首末 seq 的 uint32 差 + 1)`，仅对同一次启动、无长时回绕歧义的段使用，重复行不重复计数；同时计算板端时间间隔，否则任务停发期间序号不增加会掩盖中断。拒绝组数必须报告首值、末值和增量，不能简单除以 CSV 行数称作 CAN 丢包率。

完整验收还需要以下非数值条件：全部适用用例有原始证据；失败记录未删除；本轮修改参数后的相关用例重新通过；实际运行范围没有超出测试覆盖。停止距离、最高允许功率/温度由本车已有规范和本次场地上限约束，在 `thresholds.md` 中填实值，不在这里凭空替车定值。
